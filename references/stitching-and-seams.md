# Stitching and seams

Stitch is not "concatenate the files and ship it." It orders verified batches,
reports every problem a seam can have, and then a real editing pass — the seam
pass — fixes what the report finds before anything reaches a format skill.

## How `stitch` orders units and what the report contains

`bse.py stitch` walks PLAN.md's unit table **in table order** (execution order,
not dependency order — the plan author is responsible for those matching). For
each unit with a `done` status and an existing artifact, it inserts the file's
content under an `<!-- BSE <ID> — <title> -->` marker; for any other unit, it
inserts `<!-- MISSING <ID> -->`. It never opens a batch file for writing —
tested behavior (`test_stitch_never_modifies_batches_and_reports_terminology`)
guarantees `batches/*.md` are byte-identical before and after.

**Refusal rule:** `stitch` refuses outright (exit 1, no draft.md written)
whenever *any* unit — `[P]` or not — is not `done` with an artifact on disk,
unless `--partial` is passed. Passing `--partial` doesn't hide the gap: it
prints `WARNING: PARTIAL stitch — N unit(s) missing: ...` to stderr, lists the
missing units in `reports/stitch.md`, and inserts a `<!-- MISSING <ID> -->`
marker in `draft.md` at each one's place — so a partial stitch is always
visibly partial, never silently short.

`reports/stitch.md` (also emitted as the `--json` payload) contains:

| Section | Content |
|---|---|
| Per-unit word counts | Each unit's actual word count next to its budget, or `MISSING` |
| Total vs. target | Sum of all units' words against the charter's total size, with drift % |
| Duplicate-content report | Every normalized sentence of ≥12 words appearing in 2+ units, and which units |
| Terminology violations | Every charter terminology-lock "wrong form" found in any unit's text, with unit and line |
| Seams | For each adjacent pair of completed units, the last 30 words of the first and first 30 words of the second |
| Seam-pass files | Whether `front-matter.md`/`back-matter.md` were included, suppressed, or not yet written; a fixed note that `final.md` is never generated by `stitch` |

The duplicate and terminology scans run over prose only (fenced code and HTML
comments excluded, same rule as everywhere else in the tool).

**Budget drift now gates the exit code, on a complete stitch.** When every
unit is present (no `--partial` markers) and the stitched total drifts more
than ±20% from the charter's target for that denomination, `stitch` prints a
`WARNING: BUDGET DRIFT` line and exits 1 — the same signal `plan --validate`
gives for a plan whose budgets don't sum correctly, just caught again at
assembly time in case units drifted from their own budgets individually.
Pass `--allow-drift` to accept the size anyway and exit 0 (the report and
warning are still printed either way). A partial stitch is never drift-gated
— it's under target by construction, and the gate would just restate that.

## The seam pass: a numbered procedure

Run this against `draft.md` and `reports/stitch.md` after every stitch, before
handing off to a format skill. It is editing work, not a formality — budget
real time for it. It produces `final.md`, `front-matter.md`, and
`back-matter.md` — three files no command writes for you.

0. **Read the whole draft once against the charter's through-line.** Before
   touching any individual seam, read `draft.md` start to finish and ask
   whether the through-line — the one sentence the charter states as what
   this deliverable argues or establishes — is actually there in the
   assembled text, not just present in each unit's brief. A document written
   in N blind pieces can be locally flawless, pass every mechanical check,
   and collectively say nothing: the through-line was in every brief, but no
   unit was responsible for the document *making its case as a whole*. If
   it's missing, this is **a re-plan, not an edit** — no amount of local
   transition repair (steps 1-6 below) inserts an argument that no unit was
   ever asked to carry. Stop, go back to PLAN, and add or re-scope whatever
   unit should have carried it, before doing any of the following steps on
   what already exists.
1. **Duplicate removal.** For each entry in the duplicate-content report,
   decide which occurrence is more complete or better-placed; delete the
   other, and add a one-clause bridge if its removal leaves a gap in logic.
   Don't delete both — the report flags repetition, not content to cut
   entirely.
2. **Transition repair.** At every boundary in the seam list, read the last-30
   / first-30 word pair together. If unit *B* opens as though unit *A* never
   happened (a topic shift with no acknowledgment) or over-recaps what *A* just
   said, rewrite the opening sentence of *B* only — never reach back into *A*,
   which is already verified and recorded.
3. **Terminology conformance.** Fix every hit in the terminology-violations
   list to the approved form. This is mechanical once flagged — do it exhaustively,
   not spot-checked, since the lock exists precisely so nothing here is a judgment call.
4. **Pronoun / antecedent continuity across boundaries.** The stitch report
   won't catch this one: read each seam and confirm every pronoun in *B*'s
   opening still resolves to something *B* itself introduces or that survived
   from *A*'s closing content, not to something that was cut in step 1.
5. **Register drift.** Read two or three seams aloud (or have a single
   reviewer pass read the whole draft in one sitting). Formality, sentence
   length, and person (first/third) should not visibly shift at unit
   boundaries — that's the signature of independently-executed units, and it's
   what this pass exists to erase.
6. **Redundant re-introduction of concepts.** A term or interface each unit's
   `produces:` field defines should be *defined* once and *used* thereafter.
   If unit *D* re-explains something unit *B* already established, cut the
   re-explanation — this is what carry.md's "do not repeat" section is meant
   to have prevented, so a hit here is also a signal to sharpen that section
   for future runs.
7. **Front and back matter, written last.** Only now — after the seam pass
   confirms what the body actually says — write the introduction, executive
   summary, and conclusion into `front-matter.md` and `back-matter.md`
   respectively (both live at the run root, both start as prose-free
   placeholders from `init`).
8. **Write `final.md`.** Copy the repaired body plus front/back matter into
   `final.md` by hand. `bse.py stitch` will not do this step for you and
   actively refuses `--out final.md` — `draft.md` is regenerated machine
   output and `final.md` is the one file in the run that is never
   regenerated, only hand-written.

## Why intros and conclusions must come last

An introduction makes promises about what follows; a conclusion asserts what
was established. Both are only true statements once the body they describe
exists in its final, seam-repaired form. Writing them earlier means guessing —
and a guess that turns out wrong is now the reader's first or last impression.
This is also why executors are forbidden from writing concluding language
mid-draft (`no_conclusion`, checked on every non-final unit): a chunk that
wraps itself up preempts the one pass that's actually positioned to do it
correctly, and produces exactly the kind of duplicate/contradictory closing
language step 1 and step 6 above have to clean up.

## A stitched draft over or under the charter target

`reports/stitch.md` reports drift the same way `plan --validate` does, against
the same ±20% band (and, on a complete stitch, `stitch` itself exits 1 over
that band unless `--allow-drift` — see above). The fix is never to hand-edit
`draft.md` — it's regenerated by `stitch` and any manual edit is silently
discarded on the next run. It is also never to skip straight to re-stitching
and calling that the fix: fixing size is a **unit-level** operation, and
re-stitching only reflects a correction that was actually made at the unit
level. The procedure, in order:

1. **Fix it at the unit level.**
   - **Over target:** look at the duplicate-content report first — cut
     repetition before cutting original content. If that's not enough,
     identify the specific unit(s) carrying the excess and re-open them as a
     `revise` unit through the normal BRIEF → EXECUTE → VERIFY → RECORD loop,
     tightened to a smaller budget.
   - **Under target:** do not pad an existing unit past its own budget to
     compensate — that just breaks its own `word_count` predicate. Add a new
     `research`/`compose` unit to PLAN.md for the missing content, run it
     through the full loop.
2. **Re-run `bse.py plan --validate`**, since a new or re-scoped unit changes
   the budget-sum check.
3. **Re-stitch `draft.md`.** This regenerates the mechanical assembly from
   the now-corrected units — it does not by itself fix anything the seam
   pass already repaired, because the seam pass's work lives in `final.md`,
   a separate file `stitch` never touches or regenerates.
4. **Redo the seam pass into `final.md`.** A `draft.md` that changed after
   `final.md` was written is exactly what `FINAL_STALE` in `bse.py audit`
   exists to catch — treat that finding as instruction to repeat the seam
   pass on the new draft, not as something to silence.

## Handing off to the format skill

Once the seam pass has written `final.md`, that file — not `draft.md` — is
what goes to whatever skill renders `.docx`/`.pptx`/`.xlsx`/`.pdf`. What must
**not** happen before that point: no batch, no brief, and no intermediate
artifact is ever written directly in a binary format — everything up to and
including the seam pass is markdown, so that every stage stays diffable,
greppable, and re-verifiable by the mechanical checks in
[verification.md](verification.md). A format skill that receives `draft.md`
instead of `final.md`, or a `final.md` that `bse.py audit` flags as
`FINAL_STALE`, is receiving unverified or stale content — it should refuse,
the same way `stitch` refuses an incomplete plan.
