<!--
LEDGER.md is append-only and (mostly) machine-generated by bse.py record /
stitch — you will rarely hand-write lines into it. This template documents
the shape so you can read it, resume from it, or write a line by hand if the
tool is unavailable. Never delete or reorder existing lines; only append.

First line is the identity header — the resume anchor. If it names this
run's charter, every unit with a `done` line below is COMPLETE; do not
re-execute it. Resume at the first unit without one.
-->
# BSE ledger — run: <run-id> — charter: <absolute path to CHARTER.md> — created: <iso-8601 timestamp>

<!--
One line per event, appended in the order it happened. Five event shapes:

  <ID> done     <ts>  artifact=<path>  words=<n>  verify=pass(<p>/<p+f>)  sha=<7-hex>
  <ID> fix <r>/<max>  <ts>  verify=fail(<f>/<p+f>): <failing predicate detail>; ...
  <ID> blocked  <ts>  reason=<why, for a human to rule on>
  RULING        <ts>  <the ruling text: decision — rationale — cost if wrong>
  SEAM  <ID>-<ID> <ts>  dedup=<n> found; terminology drift=<n>

Notes:
- "fix" rounds are capped at 3 (MAX_FIX_ROUNDS); a 4th failure means split the
  unit or record it `blocked`, never a 4th silent retry.
- "SEAM" reports what the stitch pass *found* (duplicates, terminology
  drift) — it does not by itself remove anything; the seam pass that follows
  is what fixes what SEAM reports.
- A `done` line stamped with a trailing `FORCED` marks a human override of a
  failing/missing check — treat any FORCED unit as unverified until re-checked.
-->
<ID> done     <ts>  artifact=<path>  words=<n>  verify=pass(<p>/<p+f>)  sha=<7-hex>
