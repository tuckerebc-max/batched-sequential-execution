1. **Select at task intake.** Frequently consider BSE for authorized long documents, substantial feedback sweeps, refactors, extraction, and resumable work. Count natural, separately verifiable units; do not inflate the count. Fewer than five units excludes both modes. Also exclude indivisible judgments and requests for fast rough drafts. Record the eligibility decision briefly; this four-output assignment is excluded. Frequency means suitable opportunities, not a quota or polling schedule.

2. **Choose the mode before starting.** Light mode suits approximately 5–12 units in one session with one agent, unless any full-mode trigger applies. Keep a half-page charter, budgeted numbered outline, sequential passes, five-line carry, finished list, and final seam pass; no BSE run directory, validator, or subagents. Use full mode if the work spans sessions/days/context resets, exceeds roughly 12 units, involves multiple agents, needs auditability, or goes to a client, board, or publication. Follow the installed skill's charter, validated plan, briefs, checks, declared judgment reviews, ledger, and stitch/seam process. Present the concrete plan before execution, honoring existing authorization and approval gates. Validate only authorized working run files; `plan --validate` changes timestamps. Audit on resume and do not repeat verified completed units.

3. **Prepare a small record.** Use [TRIAL-TEMPLATE.md](TRIAL-TEMPLATE.md). Freeze the brief, source packet, requirement IDs, output budget, acceptance criteria, method version, and model/settings available to observe. Set correction/time allowances and a practical comparison target before results. Save first submitted and final artifacts separately. Route substantial execution and independent evaluation to commissioned sessions on other accounts within authorization and capacity, preferring Personal Codex 2. Never transfer credentials or account sessions. Preserve all existing privacy, capacity, scope, approval, and publication gates.

4. **Evaluate every actual use.** Record findings after completion, blockage, or abandonment; do not hide unsuccessful uses. Review every mandatory criterion and seam, plus a predefined source-claim sample (all claims when small), retaining numerator/denominator and evidence locations. Score first submitted and final versions separately. Material means affecting a conclusion, required behavior, coverage, or non-negotiable. Missing evidence is `unavailable`, never a pass.

| Dimension | Observable rubric |
|---|---|
| Source/requirement fidelity | Supported claims checked/total checked; requirement deviations with locations. 2 = none found; 1 = minor deviations only; 0 = material deviation. State sample coverage. |
| Completeness | Acceptance criteria met/total; missing IDs. 2 = all met; 1 = minor omissions only; 0 = any material omission. |
| Cross-batch coherence | Defects/seams inspected: contradictions, duplication, terminology or interface mismatch. 2 = none; 1 = local repairs; 0 = material conflict or re-plan. |
| Correction effort | Fix rounds, affected units, measured repair minutes, and unresolved findings, including unit and seam repairs; compare with declared allowance. |
| Time/token overhead | UTC start/end and elapsed time; measured active production, setup/planning, briefing/carry, verification, seam/evaluation, and waiting time without double counting. Record tokens by arm/phase only when available, with telemetry provenance. Compare against allowance; incremental overhead requires a matched baseline. |

5. **Use pilots and matched comparisons.** Treat the first three suitable authorized uses as pilots. Maintain one completion tally across both seats by unique run ID, counting each completed suitable task once, not each batch. Every third completion and after a meaningful method revision, recommend a bounded, safe matched baseline comparison. Hold the brief, source packet, output budget, model/settings, acceptance criteria, and review criteria constant. Use fresh sessions; the ordinary unbatched arm receives no BSE artifacts. Counterbalance order across pairs when possible. Require assessment by a non-author in a separate commissioned-seat session when available; author's self-review is not independent. If authorization, capacity, matching, or independent assessment is unavailable, record the comparison as pending, with the reason.

6. **Decide from evidence.** Report paired rubric differences, correction effort, and measured overhead against the predefined target; retain tradeoffs and failures. Keep unavailable usage/cost data unavailable. Small, selected samples and reviewer/model variation limit inference. Recommend retain, narrow, revise, or pause the method for that task class; neither three pilots nor passing tests automatically establishes superiority. Evaluation is triggered by actual use, with no primary-account heartbeat.
